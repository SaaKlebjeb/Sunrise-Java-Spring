# A JWT cannot be cancelled

The API accepts a valid JWT by checking its **signature** — no lookup of the token.

<v-clicks>

- Dara logs out → the token still works
- Dara's phone is stolen → the token still works

# Two tokens, two jobs

| | Access token | Refresh token |
|---|---|---|
| Is | a signed JWT | 32 random bytes |
| Lives | **15 minutes** | **7 days** |
| Sent | on every request | only to `POST /auth/refresh` |
| Checked by | its signature | a lookup in `refresh_tokens` |
| Cancellable | no | **yes** |

# Making one

```java
@Transactional
public String issue(String email) {
  byte[] bytes = new byte[32];
  RANDOM.nextBytes(bytes);
  String token = Base64.getUrlEncoder().withoutPadding().encodeToString(bytes);

  Instant expiresAt = Instant.now().plus(Duration.ofMillis(refreshExpirationMs));
  refreshTokenRepository.save(new RefreshToken(hash(token), email, expiresAt));
  return token;
}
```

<div class="opacity-70 text-sm"><code>SecureRandom</code>, not <code>Random</code> — unpredictable is the whole point.</div>

# Reuse detection: the theft alarm

<div class="grid grid-cols-2 gap-4 mt-4 text-sm">
<div class="p-3 rounded-lg border-2 border-green-600 bg-green-500/10"><b>Dara</b> refreshes with R2 → R2 revoked, she gets R3</div>
<div class="p-3 rounded-lg border-2 border-red-500 bg-red-500/10"><b>Thief</b> refreshes with R2 → R2 is <b>revoked</b>… but it came back</div>
</div>

<v-clicks>

- Two people had R2. We can't tell which is Dara.
- So **revoke every refresh token she has**.
- The thief is out. Dara is out too — and logs in with the password the thief doesn't have.

</v-clicks>

# The code

```java {all|8-12|13-15|17-18}
@Transactional(noRollbackFor = InvalidRefreshTokenException.class)
public String use(String token) {
  RefreshToken stored =
      refreshTokenRepository
          .findByTokenHash(hash(token))
          .orElseThrow(() -> new InvalidRefreshTokenException("unknown refresh token"));

  if (stored.isRevoked()) {
    // A used token came back: someone has a copy. End every session of this user.
    refreshTokenRepository.revokeAllFor(stored.getEmail());
    throw new InvalidRefreshTokenException("refresh token already used");
  }
  if (stored.getExpiresAt().isBefore(Instant.now())) {
    throw new InvalidRefreshTokenException("refresh token expired");
  }

  stored.setRevoked(true);
  return stored.getEmail();
}
```

---

# A transaction that must *not* roll back

<div class="p-4 rounded-lg border-2 border-red-500 bg-red-500/10 mt-4">

`use` calls `revokeAllFor` — then **throws**.

By default, an exception rolls the transaction back. The revoke would be **undone**. The thief stays in.

</div>

```java
@Transactional(noRollbackFor = InvalidRefreshTokenException.class)
```

<div class="mt-4">Session 10: <code>@Transactional</code> is all-or-nothing. Here, <i>nothing</i> is the wrong answer.</div>

# `revokeAllFor` — Session 10's `@Modifying`

```java
public interface RefreshTokenRepository extends JpaRepository<RefreshToken, Long> {
  Optional<RefreshToken> findByTokenHash(String tokenHash);

  @Modifying
  @Query("update RefreshToken t set t.revoked = true where t.email = :email and t.revoked = false")
  int revokeAllFor(@Param("email") String email);
}
```

One `update` statement instead of loading every row.

# The service grows

```java
public interface AuthService {
    AppUser register(AppUser user, String password);
    AuthResponse login(String email, String password);
    // Swap an unused refresh token for a new pair. The old one is used up
    AuthResponse refresh(String refreshToken);
    // Revoke the refresh token. The access token still works until it expires
    void logout(String refreshToken);
}
```

```java
public record AuthResponse(String token, String refreshToken, String tokenType, long expiresIn, String email) {}
```

# `login` and `refresh` end the same way

```java
@Override
public AuthResponse refresh(String refreshToken) {
  String email = refreshTokenService.use(refreshToken);
  // Load the user again: a changed role or a removed user shows up here
  return tokensFor(userDetailsService.loadUserByUsername(email));
}

private AuthResponse tokensFor(UserDetails user) {
  return new AuthResponse(
      jwtService.generateToken(user),
      refreshTokenService.issue(user.getUsername()),
      "Bearer",
      jwtService.expirationSeconds(),
      user.getUsername());
}
```

# The weakness built into what we built

**Our API stores passwords.** So it must also:

- hash them — done
- reset them, by email
- lock accounts after too many guesses
- offer two-factor login
- …and get **every one** of those right

<div class="mt-4 p-3 rounded-lg border-2 border-blue-500 bg-blue-500/10">
And every new site asks people for one more password. Most sites now offer <b>"Log in with Google / GitHub"</b> instead. The rules for that conversation are <b>OAuth2</b>.
</div>

# Wait — we said `STATELESS`

Between step 2 and step 4, the API must **remember** the `state`.

<div class="grid grid-cols-2 gap-6 mt-4">
<div class="p-4 rounded-lg border-2 border-amber-500 bg-amber-500/10">

**During the GitHub trip**

Spring keeps the `state` in a session — about a minute. A `JSESSIONID` cookie appears.

</div>
<div class="p-4 rounded-lg border-2 border-green-600 bg-green-500/10">

<code>STATELESS</code> means Spring never keeps <b>who is logged in</b> in a session. The GitHub trip keeps only its own small note. One chain is enough.

# Find or create

```java {all|4-7|10-14|20-21}
@Override
@Transactional
public AuthResponse loginWithGitHub(GitHubProfile profile) {
  // Seen this GitHub account before? Use its user. First time? Create one.
  AppUser user = appUserRepository.findByGithubId(profile.id())
      .orElseGet(() -> createGitHubUser(profile));
  return tokensFor(user);   // AppUser is a UserDetails
}

private AppUser createGitHubUser(GitHubProfile profile) {
  // GitHub sends no email if the person keeps it private
  String email = profile.email() != null ? profile.email()
      : profile.id() + "+" + profile.login() + "@users.noreply.github.com";
  if (appUserRepository.existsByEmail(email)) {
    throw new EmailAlreadyExistsException("email: " + email + " already registered");
  }
  AppUser user = new AppUser();
  user.setEmail(email);
  user.setFullName(profile.name() != null ? profile.name() : profile.login());
  user.setRole(Role.USER);
  user.setGithubId(profile.id());
  return appUserRepository.save(user);
}
```

```java {all|1|9-11}
          .failureHandler(gitHubLoginHandler))
      .authenticationProvider(authenticationProvider())
      .addFilterBefore(jwtAuthenticationFilter, UsernamePasswordAuthenticationFilter.class);
  return http.build();
}
```

# The entry point reads it

```java
@Component
public class JsonAuthenticationEntryPoint implements AuthenticationEntryPoint {

  @Override
  public void commence(
      HttpServletRequest request, HttpServletResponse response, AuthenticationException ex)
      throws IOException {
    Object reason = request.getAttribute(JwtAuthenticationFilter.REJECTED_TOKEN);
    String detail = reason != null ? reason.toString()
        : "No token. Log in and send it as: Authorization: Bearer <token>";
    ProblemDetailWriter.write(request, response, 401, "Not signed in", detail);
  }
}
```

---

# One writer, the API's error shape

```java
final class ProblemDetailWriter {
  static void write(HttpServletRequest request, HttpServletResponse response,
                    int status, String title, String detail) throws IOException {
    response.setStatus(status);
    response.setContentType("application/problem+json");
    response.setCharacterEncoding("UTF-8");
    response.getWriter().write(
        "{\"title\":\"%s\",\"status\":%d,\"detail\":\"%s\",\"instance\":\"%s\"}"
            .formatted(title, status, detail, request.getRequestURI()));
  }
}
```

<div class="opacity-70 text-sm">The same four fields as <code>GlobalExceptionHandler</code>'s ProblemDetails — the front-end reads every error one way.</div>

# And 403 gets one too

```java
@Component
public class JsonAccessDeniedHandler implements AccessDeniedHandler {

  @Override
  public void handle(
      HttpServletRequest request, HttpServletResponse response, AccessDeniedException ex)

}
```

# CORS

Letting a browser call you

---

# Two origins

**Origin** = scheme + host + port.

<div class="grid grid-cols-2 gap-4 mt-4">
<div class="p-4 rounded-lg border-2 border-blue-500 bg-blue-500/10">

`http://localhost:5173`

the web app

</div>
<div class="p-4 rounded-lg border-2 border-blue-500 bg-blue-500/10">

`http://localhost:8080`

the API

</div>
</div>

<div class="mt-4">Different ports → <b>different origins</b>. By default a browser lets a page call only its own — the <b>same-origin policy</b>.</div>

---

# The preflight

The browser asks first:

```
OPTIONS /recipes
Origin: http://localhost:5173
Access-Control-Request-Method: POST
Access-Control-Request-Headers: authorization, content-type
```

and sends the real `POST` only if the answer says yes:

```
200
Access-Control-Allow-Origin: http://localhost:5173
Access-Control-Allow-Headers: authorization, content-type
```

---

# The configuration

```java
@Bean
CorsConfigurationSource corsConfigurationSource() {
  CorsConfiguration config = new CorsConfiguration();
  config.setAllowedOrigins(allowedOrigins);
  config.setAllowedMethods(List.of("GET", "POST", "PUT", "DELETE", "OPTIONS"));
  config.setAllowedHeaders(List.of("Authorization", "Content-Type"));
  config.setMaxAge(3600L);
  UrlBasedCorsConfigurationSource source = new UrlBasedCorsConfigurationSource();
  source.registerCorsConfiguration("/**", config);
  return source;
}
```

```java
.cors(Customizer.withDefaults())
```

```properties
app.cors.allowed-origins=http://localhost:5173,http://localhost:3000
```

# Wiring both into the chain

```java {all|3|8-10|11}

```

<div class="opacity-70 text-sm">The JSON entry point replaces Session 11's <code>HttpStatusEntryPoint</code> — still a 401, never the 302 to GitHub.</div>

# Three things people get wrong

<div class="grid grid-cols-3 gap-4 mt-4">
<div class="p-4 rounded-lg border-2 border-amber-500 bg-amber-500/10">

**Only browsers enforce it**

`curl` and Postman ignore CORS. It protects users' browsers — it is **not** access control.

</div>
<div class="p-4 rounded-lg border-2 border-red-500 bg-red-500/10">

**Never `*` with credentials**

Any website could act as your user. List the real front-ends.

</div>
<div class="p-4 rounded-lg border-2 border-blue-500 bg-blue-500/10">

**Origins are config**

Laptop and server differ → a property, not code.

</div>
</div>

---

# The preflight comes before the rules

<div class="p-5 rounded-lg border-2 border-blue-500 bg-blue-500/10 mt-4">

A preflight carries **no token**. If the rules ran first, every preflight to `POST /recipes` would be 401 — and the browser would never send the real request.

`.cors(...)` puts Spring's `CorsFilter` early in the chain, so the preflight is answered first.

</div>

---

# Pause

The web team says "CORS is blocking us — just put `allowedOrigins("*")`."

<v-click>

<div class="mt-4 p-3 rounded-lg border-2 border-green-600 bg-green-500/10">
No: with an <code>Authorization</code> header, <code>*</code> lets any website call the API as the user. Ask for the exact origin their app runs on — <code>http://localhost:5173</code> today, the real domain on the server.
</div>

</v-click>

```yaml
package:
  stage: package
  image: docker:27
  services:
    - docker:27-dind
  rules:
    - if: $CI_COMMIT_BRANCH == $CI_DEFAULT_BRANCH
  script:
    - echo "$CI_REGISTRY_PASSWORD" | docker login -u "$CI_REGISTRY_USER" --password-stdin "$CI_REGISTRY"
    - docker build -t "$CI_REGISTRY_IMAGE:$CI_COMMIT_SHORT_SHA" .
    - docker push "$CI_REGISTRY_IMAGE:$CI_COMMIT_SHORT_SHA"
```

| Idea | Where |
|---|---|
| Stages run in order; red stops everything | `test` → `package` |

# Where you ended up

| Request | Answer |
|---|---|
| `POST /auth/login` | access token **and** refresh token |
| `POST /auth/refresh` with a fresh refresh token | a **new** pair — the old one is used up |
| `POST /auth/refresh` with a used one | **401** — and every refresh token of that user dies |
| `POST /auth/logout` | **204** — that refresh token is revoked |
| `/oauth2/authorization/github` in a browser | GitHub → back with **our** tokens after the `#` |
| `GET /me` with no token | **401** — never a redirect to GitHub |
| `docker compose up --build` | the API and PostgreSQL, schema `001`–`006` |

# Missing — security

| Missing | Why it matters |
|---|---|
| **Refresh tokens per device** | our alarm logs Dara out everywhere; real systems end only the affected device |
| **Refresh token in an `HttpOnly` cookie** | the safest browser setup — and CSRF protection comes back for it |
| **Linking accounts** | Dara with a password *and* GitHub is two rows today — we refuse the second |
| **Provider-issued tokens** | large systems accept Keycloak's or Entra ID's JWT — `oauth2ResourceServer()` |
| **Key rotation, RS256, JWKS** | one HS256 secret forever is a risk |
| **Rate limiting on login** | nothing stops a thousand guesses a minute at `/auth/login` |

# Recap — tokens

- A JWT can't be cancelled → **15 minutes**
- A refresh token: **random**, stored **hashed**, works **once**, a reused one **revokes everything**
- `noRollbackFor` keeps the revoke when the method throws
- Logout revokes the refresh token; the access token runs out on its own
- **OAuth2**: GitHub checks the password, sends back a **code**, used **once**, guarded by `state`
- Find the user by **`github_id`**, then hand out **our** tokens — the rest of the API doesn't know
- Errors from the chain need an **entry point** — advice can't reach them · **CORS**: real origins, never `*`

---

# Recap — shipping

- A **two-stage Dockerfile** ships a runtime and a jar, as a non-root user
- **Compose** wires the app to `db` by name, keeps data in a volume, waits for **healthy**
- Secrets come from **`.env`** — never Git, never the image
- Environment variables override `application.properties` — **one jar, everywhere**
- A **pipeline** tests every push against real PostgreSQL and tags each image with its commit
